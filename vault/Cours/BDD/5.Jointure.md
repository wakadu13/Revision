# SQL — Jointures
Retour : [[00 - Sommaire BDD|Sommaire]] · Précédent : [[4.ComplementSQL]] · Suite : [[6.Agregation]]

> [!info] Résumé en 2 phrases
> Une jointure permet de croiser les données de plusieurs tables grâce à une clé étrangère. Il existe deux familles : les jointures **internes** (seules les correspondances) et **externes** (tout d'un côté ou des deux).

---

## Rappel — Pourquoi joindre ?

- Une clé étrangère (`FK`) dans une table **référence** la clé primaire (`PK`) d'une autre
- Sans jointure, impossible d'afficher des données issues de deux tables différentes

```
Militaire (codeMili, nom, prenom, code_unite*)
                                      ↓
Unite (code, libelle)
```

---

## Syntaxe générale

```sql
SELECT colonnes
FROM tableA
[TYPE DE] JOIN tableB ON tableA.colonne = tableB.colonne;
```

> [!warning] Ancienne syntaxe — À ne pas reproduire
> ```sql
> -- ❌ Obsolète
> SELECT Militaire.nom, Unite.libelle
> FROM Militaire, Unite
> WHERE Militaire.code_unite = Unite.code;
> ```

---

## 1. Jointure Interne — INNER JOIN

> [!abstract] INNER JOIN
> Retourne uniquement les lignes ayant une **correspondance dans les deux tables**. Les lignes sans correspondance sont ignorées.

```sql
SELECT Militaire.nom, Unite.libelle
FROM Militaire
JOIN Unite ON Militaire.code_unite = Unite.code;
```

- `JOIN` = `INNER JOIN` (formes équivalentes)
- Équivalent à l'**intersection** des deux tables

---

## 2. Jointures Externes

| Jointure | Ce qu'on garde | NULL si... |
|---|---|---|
| `LEFT JOIN` | Toutes les lignes de **gauche** | Pas de correspondance à droite |
| `RIGHT JOIN` | Toutes les lignes de **droite** | Pas de correspondance à gauche |
| `FULL JOIN` | Toutes les lignes des **deux** | Pas de correspondance de chaque côté |

```sql
-- LEFT JOIN
SELECT colonnes FROM tableA
LEFT JOIN tableB ON condition;

-- RIGHT JOIN
SELECT colonnes FROM tableA
RIGHT JOIN tableB ON condition;

-- FULL JOIN
SELECT colonnes FROM tableA
FULL JOIN tableB ON condition;
```

---

## 3. Types de Conditions de Jointure

> [!abstract] Équijointure
> Condition basée sur une **égalité** (`=`). Cas le plus courant, presque toujours associée à un `INNER JOIN`.
> ```sql
> ON Militaire.code_unite = Unite.code
> ```

> [!abstract] Thétajointure
> Condition basée sur un opérateur **autre que** `=` : `<`, `>`, `<=`, `>=`, `!=`.
> ```sql
> ON produit.prix > promotion.prix_min
> ```

> [!abstract] NATURAL JOIN
> Utilisable quand les colonnes de jointure portent **le même nom** dans les deux tables. La condition est devinée automatiquement.
> ```sql
> -- Fonctionne si code_unite existe dans les deux tables
> SELECT * FROM Militaire NATURAL JOIN Unite;
> ```

> [!warning] NATURAL JOIN — À utiliser avec précaution
> Si plusieurs colonnes partagent le même nom, la jointure peut être incorrecte. Préférer `JOIN ... ON` pour plus de contrôle.

## Corrigés — BDD Pokémon

```sql
-- 1. Nom et type principal des Pokémons
SELECT pokemon.nom, type.nom
FROM pokemon
JOIN type ON pokemon.type_principal = type.id;

-- 2. Nom des dresseurs avec leur région
SELECT dresseur.nom, region.nom
FROM dresseur
JOIN region ON dresseur.id_region = region.id;

-- 3. Nom des arènes avec leur type favori
SELECT arene.nom, type.nom
FROM arene
JOIN type ON arene.type_favori = type.id;

-- 4. Pokémons de chaque dresseur
SELECT dresseur.nom, pokemon.nom
FROM dresseur
JOIN posseder ON dresseur.id = posseder.id_dresseur
JOIN pokemon ON posseder.id_pokemon = pokemon.id;

-- 5. Pokémons avec type principal triés par nom
SELECT pokemon.nom, type.nom
FROM pokemon
JOIN type ON pokemon.type_principal = type.id
ORDER BY pokemon.nom ASC;

-- 6. Pokémons dont le type principal est "Feu"
SELECT pokemon.nom
FROM pokemon
JOIN type ON pokemon.type_principal = type.id
WHERE type.nom = 'Feu';

-- 7. Dresseurs de moins de 18 ans avec leur région
SELECT dresseur.nom, dresseur.age, region.nom
FROM dresseur
JOIN region ON dresseur.id_region = region.id
WHERE dresseur.age < 18;

-- 8. Pokémons de type "Psy" avec PV entre 50 et 100
SELECT pokemon.nom
FROM pokemon
JOIN type ON pokemon.type_principal = type.id
WHERE type.nom = 'Psy'
AND pokemon.pv BETWEEN 50 AND 100;

-- 9. Pokémons capturés après 2020
SELECT pokemon.nom
FROM pokemon
JOIN posseder ON pokemon.id = posseder.id_pokemon
WHERE YEAR(posseder.date_capture) > 2020;

-- 10. Arènes avec leur champion
SELECT arene.nom, dresseur.nom
FROM arene
JOIN dresseur ON arene.id_champion = dresseur.id;

-- 11. Badges avec arène et champion
SELECT badge.nom, arene.nom, dresseur.nom
FROM badge
JOIN arene ON badge.id_arene = arene.id
JOIN dresseur ON arene.id_champion = dresseur.id;

-- 12. Badges obtenus par les dresseurs
SELECT dresseur.nom, badge.nom
FROM dresseur
JOIN obtenir ON dresseur.id = obtenir.id_dresseur
JOIN badge ON obtenir.id_badge = badge.id;

-- 13. Dresseurs ayant obtenu des badges après 2023
SELECT dresseur.nom
FROM dresseur
JOIN obtenir ON dresseur.id = obtenir.id_dresseur
WHERE obtenir.date_obtention > '2023-01-01';

-- 14. Tous les dresseurs, même sans Pokémon
SELECT dresseur.nom, pokemon.nom
FROM dresseur
LEFT JOIN posseder ON dresseur.id = posseder.id_dresseur
LEFT JOIN pokemon ON posseder.id_pokemon = pokemon.id;

-- 15. Dresseurs sans aucun Pokémon
SELECT dresseur.nom
FROM dresseur
LEFT JOIN posseder ON dresseur.id = posseder.id_dresseur
WHERE posseder.id_pokemon IS NULL;

-- 16. Dresseur, Pokémon et type "Eau", triés par dresseur
SELECT dresseur.nom, pokemon.nom, type.nom
FROM dresseur
JOIN posseder ON dresseur.id = posseder.id_dresseur
JOIN pokemon ON posseder.id_pokemon = pokemon.id
JOIN type ON pokemon.type_principal = type.id
WHERE type.nom = 'Eau'
ORDER BY dresseur.nom ASC;
```
