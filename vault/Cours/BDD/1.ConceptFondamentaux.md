# Modèle Relationnel — Concepts Fondamentaux
Retour : [[00 - Sommaire BDD|Sommaire]] · Suite : [[2.AlgèbreRelationnel]]

> [!info] Résumé en 2 phrases
> Le modèle relationnel représente les données sous forme de tables (relations) liées entre elles par des clés étrangères, offrant une indépendance entre la structure logique et le stockage physique. Le passage du modèle conceptuel (ERD) au modèle relationnel suit des règles précises selon les cardinalités des associations.

---

## Concepts de Base

> [!abstract] Relation (Table)
> Sous-ensemble du produit cartésien d'une liste de domaines, représentable en tableau 2D. Propriétés fondamentales :
> - Pas de 2 tuples (lignes) identiques
> - L'ordre des lignes est **non significatif**
> - L'ordre des colonnes est **non significatif**

| Concept | Définition |
|---|---|
| **Attribut** | Nom d'une colonne, unique au sein de la relation |
| **Domaine** | Ensemble de valeurs acceptées par un attribut |
| **Tuple** | Une ligne de la table (une occurrence) |
| **Valeur** | Contenu d'un attribut pour un tuple donné |
| **Degré / Arité** | Nombre d'attributs de la table |

---

## Les Clés

> [!abstract] Clé Candidate
> Ensemble **minimal** d'attributs permettant d'identifier de façon **unique** un tuple. Peut être simple (1 attribut) ou composée (plusieurs attributs). Une relation possède toujours au moins une clé candidate.

> [!abstract] Clé Primaire
> Clé candidate **choisie** pour identifier les tuples. Notée par **soulignement** dans le schéma :
> `R(`<u>`A1`</u>`, A2, A3)`

> [!abstract] Clé Étrangère
> Attribut(s) d'une table référençant la clé primaire d'une **autre** table. Notée avec un **astérisque** :
> `R(A1, A2, A3*)`

### Schéma d'une relation
```
RELATION(attribut1, attribut2, attribut3*, ..., attributN)
         ─────────                          ───────────
         clé primaire                       clé étrangère
```

## Du Modèle Conceptuel (ERD) au Modèle Relationnel

### Règle générale — Les objets
```
Objet          → Table
Identifiant    → Clé Primaire
Propriétés     → Attributs
```

### Association 1:N
La relation **disparaît**. La clé primaire du côté **N** migre comme clé étrangère vers la table du côté **1**.

```
EDITEUR (Numedit, Nomedit)
LIVRE   (Numliv, Titre, Date, Numedit*)
                              ────────
                              migre depuis EDITEUR
```

### Association N:N
La relation devient une **nouvelle table**. Sa clé primaire est la **concaténation** des clés primaires des deux objets participants.

```
CLASSE   (Numclasse, Nbeleve)
SALLE    (Numsalle, Capacite)
MATIERE  (Nummat, Libelle)

ENSEIGNER (Numclasse*, Numsalle*, Nummat*, GDH)
           ───────────────────────────────
           clé primaire composée
```

### Association réflexive 1:N
La table absorbe **sa propre clé primaire** en tant que clé étrangère, renommée pour éviter les ambiguïtés.

```
EMPLOYE (Numemp, Nom, Notation, Numempchef*)
                                ───────────
                                auto-référence renommée
```

### Association réflexive N:N
Une nouvelle table est créée avec la clé primaire de l'objet **apparaissant deux fois**, renommée selon le rôle de chaque lien.

```
PERSONNE (Numpers, Nompers)
MARIAGE  (NumpersEpoux*, NumpersEpouse*, DateMariage)
```

## Règles d'Intégrité Structurelle

> [!abstract] Contrainte d'Unicité
> Deux tuples ne peuvent pas avoir les mêmes valeurs sur tous les attributs de la clé primaire.

> [!abstract] Contrainte d'Entité
> Toute relation doit posséder une clé primaire. Aucun attribut participant à la clé primaire ne peut valoir **NULL**.

> [!abstract] Contrainte Référentielle
> Toute valeur de clé étrangère doit exister comme valeur de clé primaire dans la table référencée.

> [!abstract] Contrainte de Domaine
> La valeur d'un attribut doit appartenir au domaine défini (plage ou liste de valeurs). **Déclarer un type seul est insuffisant.**

> [!warning] NULL ≠ 0 ≠ espace
> `NULL` signifie **absence de valeur connue**. Ce n'est ni zéro, ni une chaîne vide. Un attribut de clé primaire ne peut **jamais** être NULL (contrainte d'entité).
