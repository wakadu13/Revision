# Cloud Security

> [!info] Résumé en 2 phrases
> La Cloud Security regroupe l'ensemble des mesures protégeant les données et applications hébergées dans le cloud, dans un environnement mutualisé où la responsabilité est partagée entre le fournisseur et le client. Elle couvre la protection des données, la gestion des identités, la sécurité réseau et la conformité réglementaire.

---

## 1. Le Shared Responsibility Model

> [!abstract] Shared Responsibility Model
> Modèle définissant la répartition des responsabilités de sécurité entre le **cloud provider** et le **client**. Le fournisseur sécurise l'infrastructure sous-jacente ; le client sécurise ses données, applications et configurations.

| Partie | Responsabilité |
|---|---|
| **Cloud Provider** | Infrastructure physique, hyperviseurs, réseau global, disponibilité |
| **Client / Administrateur** | Données, gestion des accès, configuration des services, applications |
| **Équipes sécurité internes** | Stratégie globale, risk assessments, coordination technique et humaine |

> [!warning] Point critique
> La frontière de responsabilité varie selon le modèle de service utilisé (IaaS, PaaS, SaaS). Ne pas clarifier cette frontière est une source fréquente de misconfiguration.

---

## 2. Menaces principales

| Menace | Description |
|---|---|
| **Data breach** | Accès non autorisé à des données sensibles |
| **Insecure APIs** | Failles dans les interfaces d'accès aux services cloud, exploitables par des attaquants |
| **Misconfigured cloud storage** | Mauvais paramétrage exposant des données publiquement de façon involontaire |
| **Account hijacking** | Vol de credentials permettant à un attaquant d'usurper une identité et d'accéder aux ressources |

> [!warning] Erreur classique
> Les misconfigurations sont la cause n°1 des incidents cloud. Un bucket de stockage mal configuré peut exposer des milliers de fichiers sensibles sans qu'aucune attaque sophistiquée ne soit nécessaire.

---

## 3. Domaines clés de la Cloud Security

### 3.1 Data Protection
- **Chiffrement at rest** : données protégées lorsqu'elles sont stockées.
- **Chiffrement in transit** : données protégées lors de leur transfert sur le réseau.

### 3.2 Identity and Access Management (IAM)

> [!abstract] IAM — Identity and Access Management
> Ensemble des politiques et outils garantissant que seules les entités **autorisées** accèdent aux ressources cloud. Inclut l'authentification (MFA), la gestion des rôles et le principe du moindre privilège.

### 3.3 Network Security
- **Firewalls** : filtrage du trafic entrant et sortant.
- **VPN** (Virtual Private Network) : tunnelisation sécurisée des communications.
- Surveillance des flux réseau pour détecter les comportements anormaux.

### 3.4 Compliance & Governance
- Respect des lois et réglementations relatives à la gestion des données (ex : RGPD).
- Alignement avec les standards industriels en vigueur.
- Audits réguliers pour vérifier la conformité des pratiques.

---

## 4. Maintien dans le temps

La Cloud Security est un processus **continu**, non un état figé :

- **Patch management** : corriger les vulnérabilités connues.
- **Mise à jour des protocoles** de sécurité face aux nouvelles menaces.
- **Monitoring** : surveillance permanente des activités suspectes.
- **Security awareness** : formation des utilisateurs aux bonnes pratiques.
- **Penetration testing** : simulations d'attaques régulières pour identifier les failles avant les acteurs malveillants.
