Le **Transmission Control Protocol (TCP)** et le **User Datagram Protocol (UDP)** sont deux protocoles utilisés pour la transmission d'informations et de données sur Internet. Généralement, les connexions **TCP** transmettent des données importantes, telles que des pages web et des e-mails. En revanche, les connexions **UDP** transmettent des données en temps réel, comme la diffusion vidéo ou les jeux en ligne.

Le **TCP** est un protocole orienté connexion qui garantit que toutes les données envoyées d'un ordinateur à un autre sont bien reçues. Il fonctionne comme une conversation téléphonique où les deux parties restent connectées jusqu'à la fin de l'appel. Si une erreur se produit lors de l'envoi des données, le destinataire envoie un message de retour pour que l'expéditeur puisse renvoyer les données manquantes. Cela rend le TCP fiable, mais plus lent que l'UDP, car plus de temps est nécessaire pour la transmission et la récupération des erreurs.

L'**UDP**, en revanche, est un protocole sans connexion. Il est utilisé lorsque la vitesse est plus importante que la fiabilité, comme pour la diffusion vidéo ou les jeux en ligne. Avec l'UDP, il n'y a pas de vérification que les données reçues sont complètes et exemptes d'erreurs. Si une erreur se produit lors de l'envoi des données, le destinataire ne recevra pas ces données manquantes, et aucun message ne sera envoyé pour les renvoyer. Certaines données peuvent être perdues avec l'UDP, mais la transmission globale est plus rapide.

### **Paquet IP**

Un **paquet Internet Protocol (IP)** est la zone de données utilisée par la couche réseau du modèle **Open Systems Interconnection (OSI)** pour transmettre des données d'un ordinateur à un autre. Il se compose d'un **en-tête** et de la **charge utile**, c'est-à-dire les données réelles.

On peut aussi considérer le paquet IP comme une lettre envoyée dans une enveloppe. L'enveloppe contient l'en-tête, qui inclut les informations sur l'expéditeur et le destinataire, ainsi que les instructions pour l'acheminement de la lettre, c'est-à-dire par quels bureaux de poste elle doit passer. La lettre elle-même est la charge utile, les données réelles.

---

### **En-tête IP**

L'en-tête d'un paquet IP contient plusieurs champs qui contiennent des informations importantes.

|**Champ**|**Description**|
|---|---|
|**Version**|Indique la version du protocole IP utilisée.|
|**Longueur de l'en-tête Internet**|Indique la taille de l'en-tête en mots de 32 bits.|
|**Classe de service**|Indique l'importance de la transmission des données.|
|**Longueur totale**|Spécifie la longueur totale du paquet en octets.|
|**Identification (ID)**|Utilisé pour identifier les fragments du paquet lorsqu'il est fragmenté en parties plus petites.|
|**Drapeaux**|Utilisés pour indiquer la fragmentation.|
|**Décalage de fragment**|Indique où le fragment actuel est placé dans le paquet.|
|**Time to Live (TTL)**|Spécifie combien de temps le paquet peut rester dans le réseau.|
|**Protocole**|Spécifie le protocole utilisé pour transmettre les données (TCP, UDP, etc.).|
|**Somme de contrôle**|Utilisée pour détecter les erreurs dans l'en-tête.|
|**Source/Destination**|Indiquent d'où le paquet a été envoyé et vers où il est envoyé.|
|**Options**|Contiennent des informations optionnelles pour l'acheminement.|
|**Remplissage**|Remplit le paquet à une longueur de mot complète.|

Nous pouvons voir un ordinateur avec plusieurs adresses IP sur différents réseaux. Dans ce cas, nous devons prêter attention au champ **IP ID**. Il est utilisé pour identifier les fragments d'un paquet IP lorsqu'il est fragmenté en parties plus petites. C'est un champ de 16 bits avec un numéro unique allant de 0 à 65 535.

Si un ordinateur a plusieurs adresses IP, le champ **IP ID** sera différent pour chaque paquet envoyé par l'ordinateur, mais très similaire. Dans **TCPdump**, le trafic réseau pourrait ressembler à ceci :

```
IP 10.129.1.100.5060 > 10.129.1.1.5060: SIP, length: 1329, id 1337
IP 10.129.1.100.5060 > 10.129.1.1.5060: SIP, length: 1329, id 1338
IP 10.129.1.100.5060 > 10.129.1.1.5060: SIP, length: 1329, id 1339
IP 10.129.2.200.5060 > 10.129.1.1.5060: SIP, length: 1329, id 1340
IP 10.129.2.200.5060 > 10.129.1.1.5060: SIP, length: 1329, id 1341
IP 10.129.2.200.5060 > 10.129.1.1.5060: SIP, length: 1329, id 1342
```

Nous pouvons voir dans la sortie que deux adresses IP différentes envoient des paquets à l'adresse IP **10.129.1.1**. Cependant, grâce à l'ID IP, nous pouvons voir que les paquets sont continus. Cela indique fortement que les deux adresses IP appartiennent au même hôte dans le réseau.

### **Champ Record-Route IP**

Le champ **Record-Route** dans l'en-tête IP enregistre également le chemin vers un appareil de destination. Lorsque l'appareil de destination renvoie le paquet **ICMP Echo Reply**, les adresses IP de tous les appareils traversés par le paquet sont listées dans le champ **Record-Route** de l'en-tête IP. Cela se produit lorsque nous utilisons la commande suivante, par exemple :

```
antoinewac70@htb[/htb]$ ping -c 1 -R 10.129.143.158
```

```
PING 10.129.143.158 (10.129.143.158) 56(124) bytes of data.
64 bytes from 10.129.143.158: icmp_seq=1 ttl=63 time=11.7 ms
RR: 10.10.14.38
        10.129.0.1
        10.129.143.158
        10.129.143.158
        10.10.14.1
        10.10.14.38

--- 10.129.143.158 ping statistics ---
1 packets transmitted, 1 received, 0% packet loss, time 0ms
rtt min/avg/max/mdev = 11.688/11.688/11.688/0.000 ms
```

La sortie indique qu'une requête ping a été envoyée et qu'une réponse a été reçue de l'appareil de destination. Elle montre également le champ **Record-Route** dans l'en-tête IP du paquet **ICMP Echo Request**. Le champ **Record-Route** contient les adresses IP de tous les appareils traversés par le paquet **ICMP Echo Request** sur le chemin vers l'appareil de destination. Dans ce cas, le champ **Record-Route** contient les adresses IP suivantes :

```
10.10.14.38
10.129.0.1
10.129.143.158
10.129.143.158
10.10.14.1
10.10.14.38
```

L'outil **traceroute** peut également être utilisé pour tracer le chemin vers une destination de manière plus précise, en utilisant la méthode de timeout TCP pour déterminer quand le chemin a été entièrement tracé.

1. Nous envoyons un paquet **TCP SYN** à l'appareil de destination avec un **TTL de 1** dans l'en-tête IP.
2. Lorsque le paquet **TCP SYN** avec un **TTL supérieur à 1** atteint un routeur, la valeur du **TTL** est décrémentée de 1, et le paquet est transmis au dispositif suivant. Si le paquet **TCP SYN** avec un **TTL de 1** atteint un routeur, le paquet est abandonné, et le routeur envoie un paquet **ICMP Time-Exceeded** en retour.
3. Nous recevons le paquet **ICMP Time-Exceeded** et notons l'adresse IP du routeur qui a envoyé le paquet.
4. Ensuite, nous envoyons un autre paquet **TCP SYN** à la destination, en augmentant le **TTL de 1**.

Le processus se répète jusqu'à ce que le paquet **TCP SYN** atteigne l'hôte de destination et reçoive une réponse **TCP SYN/ACK** ou **TCP RST** de la cible. Une fois que nous recevons une réponse de l'appareil de destination, nous savons que nous avons tracé le chemin vers la destination et mis fin au processus **traceroute**.

### **Charge utile IP**

La **charge utile** (également appelée **données IP**) est la charge utile réelle du paquet. Elle contient les données de divers protocoles, tels que **TCP** ou **UDP**, qui sont transmises, comme le contenu de la lettre dans l'enveloppe.

---

### **TCP**

Les paquets **TCP**, également appelés **segments**, sont divisés en plusieurs sections appelées **en-têtes** et **charges utiles**. Les segments TCP sont enveloppés dans le paquet IP envoyé.

L'en-tête contient plusieurs champs qui contiennent des informations importantes. Le **port source** indique l'ordinateur à partir duquel le paquet a été envoyé. Le **port de destination** indique à quel ordinateur le paquet est envoyé. Le **numéro de séquence** indique l'ordre dans lequel les données ont été envoyées. Le **numéro d'accusé de réception** est utilisé pour confirmer que toutes les données ont été reçues avec succès. Les **drapeaux de contrôle** indiquent si le paquet marque la fin d'un message, s'il s'agit d'un accusé de réception que les données ont été reçues, ou s'il contient une demande de répétition des données. La **taille de la fenêtre** indique combien de données le destinataire peut recevoir. La **somme de contrôle** est utilisée pour détecter les erreurs dans l'en-tête et la charge utile. Le **pointeur urgent** alerte le destinataire que des données importantes se trouvent dans la charge utile.

La charge utile est la charge utile réelle du paquet et contient les données qui sont transmises, comme le contenu d'une conversation entre deux personnes.

---

### **UDP**

L'**UDP** transfère des **datagrammes** (petits paquets de données) entre deux hôtes. C'est un protocole sans connexion, ce qui signifie qu'il n'a pas besoin d'établir une connexion entre l'expéditeur et le destinataire avant d'envoyer des données. Au lieu de cela, les données sont envoyées directement à l'hôte cible sans connexion préalable.

Lorsque **traceroute** est utilisé avec **UDP**, nous recevrons un message **Destination Inaccessible** et **Port Inaccessible** lorsque le paquet de datagramme UDP atteint l'appareil cible. Généralement, les paquets UDP sont envoyés en utilisant **traceroute** sur les hôtes Unix.

### **Spoofing aveugle**

Le **spoofing aveugle** est une méthode d'attaque de manipulation de données dans laquelle un attaquant envoie de fausses informations sur un réseau sans voir les réponses réelles envoyées par les appareils cibles. Cela implique de manipuler le champ **en-tête IP** pour indiquer de fausses adresses source et destination. Par exemple, nous envoyons un paquet TCP à l'hôte cible avec de faux numéros de port source et destination et un faux **Initial Sequence Number (ISN)**. L'ISN est un champ dans l'en-tête TCP utilisé pour spécifier le numéro de séquence du premier paquet TCP dans une connexion. L'ISN est défini par l'expéditeur d'un paquet TCP et envoyé au destinataire dans l'en-tête TCP du premier paquet. Cela peut amener l'hôte cible à établir une connexion avec nous sans recevoir la connexion.

Cette attaque est couramment utilisée pour perturber l'intégrité des connexions réseau ou pour rompre les connexions entre les appareils réseau. Elle peut également être utilisée pour surveiller le trafic réseau ou intercepter les informations envoyées par les appareils réseau.
