# Application Security — Fondamentaux

> [!info] Résumé en 2 phrases
> L'Application Security protège les logiciels contre les threats tout au long de leur cycle de vie (SDLC), de la conception au déploiement. Elle repose sur le principe de **Security by Design** : intégrer la sécurité dès le début, pas en option finale.

---

## Cycle de Vie — Les 3 Phases

```
1. BUILD (Développement sécurisé)
      ↓
2. TEST (Recherche de vulnérabilités)
      ↓
3. MAINTAIN (Monitoring & patching continu)
```

```python
def protect_application():
    build_house()              # Développer avec sécurité intégrée
    inspect_house()            # Tester les vulnérabilités
    maintain_house_security()  # Monitorer et patcher en continu
```

---

## Phase 1 — Build : Secure Coding

| Pratique | Description |
|---|---|
| **Authentication** | Contrôle d'accès à l'application |
| **Secure Code** | Code résistant aux attaques courantes |
| **Encryption** | Protection des données en transit et au repos |

**Vulnérabilités classiques à éviter :**
- SQL Injection
- Cross-Site Scripting (**XSS**)
- Buffer Overflows

---

## Phase 2 — Test : Vulnerability Assessment

| Technique | Description |
|---|---|
| **Penetration Testing** | Simulation d'attaques réelles |
| **Static Analysis** | Analyse du code source sans exécution |
| **Dynamic Analysis** | Analyse du comportement en exécution |
| **Fuzzing** | Injection d'inputs aléatoires pour détecter des bugs |
| **Manual Code Review** | Inspection manuelle du code |

---

## Phase 3 — Maintain : Monitoring Continu

- Surveillance active des nouvelles threats
- **Patching** régulier des vulnérabilités découvertes
- Scans automatisés en continu
- Security assessments périodiques

---

## Security by Design

> [!abstract] Security by Design
> Intégrer la sécurité dès la phase de conception, pas en post-production. La sécurité est une contrainte de base, non un ajout optionnel.

Pratiques concrètes :
- **Threat Modeling** : anticiper les vecteurs d'attaque en amont
- **Secure Code Reviews** : relecture systématique du code
- Sécurisation des serveurs, bases de données, infrastructure
- **Authentication & Authorization** robustes

> [!warning] Pression temporelle
> La course au time-to-market pousse à des **raccourcis sécurité**. Chaque étape de sécurité skippée devient un vecteur d'attaque potentiel en production.

## Responsabilités

| Rôle | Responsabilité |
|---|---|
| **Developers** | Écrire du code sécurisé |
| **Security Architect** | Concevoir l'architecture sécurisée |
| **IT Operations** | Sécuriser l'environnement de production |
| **Penetration Testers** | Tester la résistance de l'application |
| **CISO / AppSec Manager** | Définir les politiques, assurer la conformité |
