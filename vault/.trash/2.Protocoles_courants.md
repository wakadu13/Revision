Les **protocoles Internet** sont des règles et directives standardisées définies dans les **RFC** (Request for Comments) qui spécifient comment les appareils sur un réseau doivent communiquer entre eux. Ils garantissent que les appareils sur un réseau peuvent échanger des informations de manière cohérente et fiable, indépendamment du matériel et des logiciels utilisés. Pour que les appareils communiquent sur un réseau, ils doivent être connectés via un canal de communication, tel qu'une connexion filaire ou sans fil. Les appareils échangent ensuite des informations en utilisant un ensemble de protocoles standardisés qui définissent le format et la structure des données transmises. Les deux principaux types de connexions utilisées sur les réseaux sont le **Transmission Control Protocol (TCP)** et le **User Datagram Protocol (UDP)**.

Nous devons connaître et maîtriser les différents protocoles les plus utilisés. Comme nous l'avons déjà appris, ces protocoles sont la base de toute communication entre nos appareils et ordinateurs dans les réseaux. Nous avons compilé ci-dessous de nombreux protocoles avec lesquels nous allons travailler tout au long des modules. Plus nous les comprenons, plus nous pouvons travailler efficacement avec eux.

### **Transmission Control Protocol (TCP)**

Le **TCP** est un protocole orienté connexion qui établit une connexion virtuelle entre deux appareils avant de transmettre des données en utilisant un **Three-Way-Handshake**. Cette connexion est maintenue jusqu'à ce que le transfert de données soit terminé, et les appareils peuvent continuer à échanger des données tant que la connexion est active.

Par exemple, lorsque nous saisissons une URL dans notre navigateur web, celui-ci envoie une requête **HTTP** au serveur hébergeant le site web en utilisant le **TCP**. Le serveur répond en envoyant le code **HTML** du site web au navigateur via le **TCP**. Le navigateur utilise ensuite ce code pour afficher le site web à l'écran. Ce processus repose sur l'établissement et le maintien d'une connexion **TCP** entre le navigateur et le serveur web jusqu'à ce que le transfert de données soit terminé. Par conséquent, le **TCP** est fiable mais plus lent que le **UDP** car il nécessite un surcoût supplémentaire pour établir et maintenir la connexion.

### **User Datagram Protocol (UDP)**

À l'inverse, le **UDP** est un protocole sans connexion, ce qui signifie qu'il ne crée pas de connexion virtuelle avant de transmettre des données. Au lieu de cela, il envoie les paquets de données à la destination sans vérifier s'ils ont été reçus.

Par exemple, lorsque nous diffusons ou regardons une vidéo sur une plateforme comme YouTube, les données vidéo sont transmises à notre appareil en utilisant le **UDP**. Cela est dû au fait que la vidéo peut tolérer une certaine perte de données, et la vitesse de transmission est plus importante que la fiabilité. Si quelques paquets de données vidéo sont perdus en cours de route, cela n'affectera pas significativement la qualité globale de la vidéo. Cela rend le **UDP** plus rapide que le **TCP**, mais moins fiable car il n'y a aucune garantie que les paquets atteignent leur destination.

### **Internet Control Message Protocol (ICMP)**

Le **protocole de contrôle des messages Internet (ICMP)** est un protocole utilisé par les appareils pour communiquer entre eux sur Internet à diverses fins, notamment le rapport d'erreurs et les informations d'état. Il envoie des requêtes et des messages entre les appareils, qui peuvent être utilisés pour signaler des erreurs ou fournir des informations d'état.

#### **Requêtes ICMP**

Une requête est un message envoyé par un appareil à un autre pour demander des informations ou effectuer une action spécifique. Un exemple de requête dans ICMP est la requête **ping**, qui teste la connectivité entre deux appareils. Lorsque l'un des appareils envoie une requête ping à un autre, le second appareil répond par un message de réponse ping.

#### **Messages ICMP**

Un message dans ICMP peut être soit une requête, soit une réponse. En plus des requêtes et réponses ping, ICMP prend en charge d'autres types de messages, tels que les messages d'erreur, les messages "destination inaccessible" et les messages "temps dépassé". Ces messages sont utilisés pour communiquer divers types d'informations et d'erreurs entre les appareils sur le réseau.

Par exemple, si un appareil tente d'envoyer un paquet à un autre appareil et que le paquet ne peut pas être livré, l'appareil peut utiliser ICMP pour envoyer un message d'erreur au destinataire. ICMP a deux versions différentes :

- **ICMPv4** : Pour IPv4 uniquement
- **ICMPv6** : Pour IPv6 uniquement

L'**ICMPv4** est la version originale de l'ICMP, développée pour une utilisation avec IPv4. Il est encore largement utilisé et est la version la plus courante de l'ICMP. En revanche, l'**ICMPv6** a été développé pour IPv6. Il inclut des fonctionnalités supplémentaires et est conçu pour résoudre certaines des limitations de l'ICMPv4.

|**Type de requête**|**Description**|
|---|---|
|Echo Request|Ce message teste si un appareil est accessible sur le réseau. Lorsqu'un appareil envoie une requête d'écho, il s'attend à recevoir un message de réponse d'écho. Par exemple, les outils **tracert** (Windows) ou **traceroute** (Linux) envoient toujours des requêtes d'écho ICMP.|
|Timestamp Request|Ce message détermine l'heure sur un appareil distant.|
|Address Mask Request|Ce message est utilisé pour demander le masque de sous-réseau d'un appareil.|

|**Type de message**|**Description**|
|---|---|
|Echo reply|Ce message est envoyé en réponse à un message de requête d'écho.|
|Destination unreachable|Ce message est envoyé lorsqu'un appareil ne peut pas livrer un paquet à sa destination.|
|Redirect|Un routeur envoie ce message pour informer un appareil qu'il doit envoyer ses paquets à un autre routeur.|
|Time exceeded|Ce message est envoyé lorsqu'un paquet a mis trop de temps à atteindre sa destination.|
|Parameter problem|Ce message est envoyé lorsqu'il y a un problème avec l'en-tête d'un paquet.|
|Source quench|Ce message est envoyé lorsqu'un appareil reçoit des paquets trop rapidement et ne peut pas suivre. Il est utilisé pour ralentir le flux de paquets.|

Une autre partie cruciale de l'ICMP pour nous est le champ **Time-To-Live (TTL)** dans l'en-tête du paquet ICMP, qui limite la durée de vie du paquet lorsqu'il circule dans le réseau. Cela empêche les paquets de circuler indéfiniment sur le réseau en cas de boucles de routage. Chaque fois qu'un paquet passe par un routeur, le routeur décrémente la valeur TTL de 1. Lorsque la valeur TTL atteint 0, le routeur rejette le paquet et envoie un message **ICMP Time Exceeded** au destinataire.

Nous pouvons également utiliser le TTL pour déterminer le nombre de sauts qu'un paquet a effectués et la distance approximative jusqu'à la destination. Par exemple, si un paquet a un TTL de 10 et effectue 5 sauts pour atteindre sa destination, on peut en déduire que la destination est à environ 5 sauts. Par exemple, si nous voyons un ping avec une valeur TTL de 122, cela pourrait signifier que nous traitons avec un système Windows (TTL par défaut 128) qui est à 6 sauts de distance.

Cependant, il est également possible de deviner le système d'exploitation en fonction de la valeur TTL par défaut utilisée par l'appareil. Chaque système d'exploitation a généralement une valeur TTL par défaut lorsqu'il envoie des paquets. Cette valeur est définie dans l'en-tête du paquet et est décrémentée de 1 chaque fois que le paquet passe par un routeur. Par conséquent, l'examen de la valeur TTL par défaut d'un appareil permet de déduire le système d'exploitation utilisé par l'appareil. Par exemple :

- Les systèmes Windows (2000/XP/2003/Vista/10) ont généralement une valeur TTL par défaut de 128.
- Les systèmes macOS et Linux ont généralement une valeur TTL par défaut de 64.
- Le système Solaris a une valeur TTL par défaut de 255.

Cependant, il est important de noter que l'utilisateur peut modifier ces valeurs, donc elles ne doivent pas être considérées comme une méthode définitive pour déterminer le système d'exploitation d'un appareil.

### **Voice over Internet Protocol (VoIP)**

Le **Voice over Internet Protocol (VoIP)** est une méthode de transmission de la voix et des communications multimédias. Par exemple, il nous permet de passer des appels téléphoniques en utilisant une connexion Internet haut débit au lieu d'une ligne téléphonique traditionnelle, comme Skype, WhatsApp, Google Hangouts, Slack, Zoom, et autres.

Les ports VoIP les plus courants sont **TCP/5060** et **TCP/5061**, utilisés pour le **Session Initiation Protocol (SIP)**. Cependant, le port **TCP/1720** peut également être utilisé par certains systèmes VoIP pour le protocole **H.323**, un ensemble de normes pour la communication multimédia sur des réseaux basés sur paquets. Cependant, le **SIP** est plus largement utilisé que le **H.323** dans les systèmes VoIP.

Le **SIP** est un protocole de signalisation pour l'initiation, le maintien, la modification et la terminaison de sessions en temps réel impliquant la vidéo, la voix, la messagerie et d'autres applications et services de communication entre deux ou plusieurs points de terminaison sur Internet. Par conséquent, il utilise des requêtes et des méthodes entre les points de terminaison. Les requêtes et méthodes SIP les plus courantes sont :

|**Méthode**|**Description**|
|---|---|
|INVITE|Initie une session ou invite un autre point de terminaison à participer.|
|ACK|Confirme la réception d'une requête INVITE.|
|BYE|Termine une session.|
|CANCEL|Annule une requête INVITE en attente.|
|REGISTER|Enregistre un agent utilisateur SIP (UA) auprès d'un serveur SIP.|
|OPTIONS|Demande des informations sur les capacités d'un serveur SIP ou d'un agent utilisateur, telles que les types de médias qu'il prend en charge.|

#### **Divulgation d'informations**

Cependant, le **SIP** nous permet d'énumérer les utilisateurs existants pour des attaques potentielles. Cela peut être fait à diverses fins, telles que déterminer la disponibilité d'un utilisateur, découvrir des informations sur les capacités ou services de l'utilisateur, ou effectuer des attaques par force brute sur les comptes utilisateurs ultérieurement.

L'une des méthodes possibles pour énumérer les utilisateurs est la requête **SIP OPTIONS**. Il s'agit d'une méthode utilisée pour demander des informations sur les capacités d'un serveur SIP ou d'agents utilisateurs, telles que les types de médias qu'ils prennent en charge, les codecs qu'ils peuvent décoder et d'autres détails. La requête **OPTIONS** peut sonder un serveur SIP ou un agent utilisateur pour obtenir des informations ou tester sa connectivité et sa disponibilité.

Lors de notre analyse, il est possible de découvrir un fichier **SEPxxxx.cnf**, où **xxxx** est un identifiant unique, qui est un fichier de configuration utilisé par **Cisco Unified Communications Manager**, anciennement connu sous le nom de **Cisco CallManager**, pour définir les paramètres et les paramètres d'un **Cisco Unified IP Phone**. Le fichier spécifie le modèle du téléphone, la version du micrologiciel, les paramètres réseau et d'autres détails.
